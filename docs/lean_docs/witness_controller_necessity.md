# Witness Controller Necessity

This note isolates the witness-side frontier of the controller-complexity
program.

The binary/sub-threshold side is close to a theorem. The dynamic recurrence side
now has a credible theorem schema. The current real frontier is:

> why must valid near-threshold systems contain a repeated-shadow controller of
> minimal deterministic size `3`?

## Current empirical invariant

Across the explicit witnesses `w4..w8`:

- some forgotten processor `p` has repeated-shadow controller capacity `3`
- the mover image on the critical repeated shadows is exactly
  `{left(p), p, right(p)}`
- the controller is deterministic in the forgotten processor’s local state
- the controller is irreducible to `2` states
- the controller is reducible to `3` states, even in the observed `m_p = 4`
  cases

So the candidate invariant is:

**minimal local controller complexity = 3 somewhere**

not merely:

**some processor has at least 3 states**

## Candidate theorem

### Theorem (Witness Controller Necessity)

Let `sys` be a valid near-threshold witness system in the target small-`n`
regime. Then there exists a processor `p` and a family of repeated `p`-shadows
on a good cycle such that:

1. the mover on those shadows is determined by the forgotten local state at `p`
2. the image of this controller is exactly `{left(p), p, right(p)}`
3. the controller has no deterministic quotient of size `2`

Equivalently: the minimal deterministic controller size at `p` is `3`.

## Why this is the right frontier

If this theorem is proved, and the sub-threshold side proves controller
complexity `<= 2`, then the lower bound is immediate.

So this is the decisive witness-side statement.

## Strong supporting evidence

### 1. `w4`

- forgetting `p = 3` gives critical shadows `(1,1,0)` and `(0,0,1)`
- both have mover set `{0,2,3}`
- the 3-state controller is irreducible to `2`

### 2. `w5`

- forgetting `p = 3` gives critical shadow `(1,1,0,0)`
- mover set `{2,3,4}`
- this can be read as fusing the sub-threshold pair-controllers `{2,3}` and
  `{3,4}`

### 3. `w6..w8`

- every critical controller found so far still has minimal deterministic size `3`
- the `m_p = 4` cases only refine one of the three branches rather than adding a
  fourth branch

## Plausible proof routes

### Route A: Local routing-memory theorem

Show that some processor must act as a local routing memory for the three local
directions `{left, self, right}`.

This is close in spirit to the older response-pattern / phase-memory notes.

Potential advantage:
- meshes with old “routing memory” and “phase confusion” ideas

Main difficulty:
- turning global good-cycle structure into a local controller statement

### Route B: Repeated-shadow escape theorem

Show that convergence requires the ability to escape the bad reuse regions
generated by deterministic `2`-controllers, and that such escape requires a
local third branch on some repeated shadow.

Potential advantage:
- directly tailored to the new controller-recurrence theorem

Main difficulty:
- formalizing “escape from bad reuse regions” in a way that is both strong enough
  and reusable

### Route C: Witness-specific lift theorem

Show that every near-threshold valid system is, in an appropriate sense, a lift
of a low-complexity shadow skeleton, and that avoiding the low-complexity trap
forces one repeated shadow to split into a 3-controller.

Potential advantage:
- matches the empirical “orientation fusion / pair fusion -> triple controller”
  story

Main difficulty:
- making “lift” precise without overfitting to the explicit witnesses

## Most promising bridge at `n=5`

The strongest current `n=5` bridge is:

- sub-threshold product-72 families at forgotten processor `p=3` show sampled
  pair-controllers `{2,3}` and `{3,4}`
- the threshold witness `w5` upgrades this to the triple-controller `{2,3,4}`

This strongly suggests the witness-side theorem may be about **fusing adjacent
pair-controllers into a triple-controller**.

## What would count as real progress next

Any one of the following would materially advance the frontier:

1. a theorem statement that makes “escape from 2-controller bad reuse regions”
   precise enough to imply controller size `3`
2. a proof that the old response-pattern lower bound implies controller
   complexity `3` in the witness regimes
3. a clean `n=5` theorem that product-72 families admit only pair-controllers,
   while `w5` forces a fused triple-controller
